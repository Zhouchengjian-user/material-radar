# 素材雷达助手

这是一个面向短视频与设计团队的本地优先素材库。图片、视频、文字和索引数据默认保存在浏览器 IndexedDB 中；腾讯 WeMM-Embedding 作为可选的语义检索服务。

## 现在可以做什么

- 批量导入图片、视频、PDF、Word、TXT、Markdown、JSON、CSV、HTML、SRT、VTT 和 ZIP 压缩包；压缩包内的素材会拆分后分别识别。
- 在综合、视频、图片、文字四个工作台中，用文字、图片或视频片段跨模态检索。
- 准确度 V2 将镜头画面、台词、OCR 与名称标签分路索引，按查询意图动态加权，并自动过滤弱匹配和重叠重复镜头。
- 连接两项服务后，默认启用“智能精细”：长镜头细分到约 2 秒，动态抽帧、连续语音识别、变化门控 OCR 与视频字幕轨共同参与检索；也可切换为快速分析。
- 每条视频都会保存分析凭证，逐项显示切镜、语音、OCR 和字幕轨是已写入、已检查无内容、失败，还是旧服务未回执。
- 粘贴分镜脚本，一次为最多 10 个镜头意图推荐首选与备选素材。
- 命中视频后从匹配时间开始预览；右侧审片器可展开为大窗口，同时保留完整原文件下载。
- 编辑标签、记录使用次数、删除素材、下载原文件和导出 JSON 索引。
- 自动跳过重复文件；长视频约每 150 秒建立一个断点，完成一块立即保存，结果读取、媒体分析和向量失败都能分别恢复。
- 显示模型真实在线状态、本地存储占用，并可向浏览器申请持久保存。

## 本地启动

需要 Node.js 20 或更高版本。首次运行先安装依赖：

```bash
npm install
npm start
```

浏览器打开 `http://127.0.0.1:4173`。

## AutoDL 部署 WeMM

推荐先使用 `tencent/WeMM-Embedding-2B` 和 256 维向量。把 `cloud` 目录上传到 AutoDL 实例后执行：

```bash
cd cloud
pip install -r requirements.txt
export WEMM_MODEL=tencent/WeMM-Embedding-2B
export RADAR_API_KEY=换成你自己的一段随机密码
bash start_autodl.sh
```

然后在 AutoDL 控制台把实例端口 `8000` 映射成公网地址。在素材雷达右上角打开模型设置，填写公网地址与同一段 API 密钥，先测试连接，再保存。

首次启动会下载并加载模型，耗时取决于网络与显卡。AutoDL 关机不会影响本地素材；再次开机后重新启动服务即可恢复自然语言检索。

## 拯救者本地部署 WeMM

RTX 5060 Laptop 8GB 使用 `cloud/install_legion.sh` 安装 CUDA 12.8 版 PyTorch 与 ffmpeg，并通过 `cloud/start_legion.sh` 以 8 位权重和每个片段最多 24 帧的视频配置启动 2B 模型：

```bash
cd cloud
bash install_legion.sh
bash configure_legion.sh
bash start_legion.sh
```

完整的 WSL2 安装与故障处理见 `outputs/拯救者-WeMM部署指南.md`。这里的 24 帧是单个 5 至 8 秒片段内部的采样上限，不是整条视频最多切 24 段。8GB 属于低显存适配方案，真机若仍出现显存不足，可将 `WEMM_VIDEO_MAX_FRAMES` 降到 12。

如果 8001 仍是旧版代表帧分析，把 `outputs/给拯救者Pi-Agent的视频近秒级精度升级提示词.md` 交给拯救者上的 Pi Agent 执行。升级后的健康接口会返回 `radar-precision-v1`，网页设置与素材详情会明确显示“智能精细已生效”。

超过 6 分钟的视频建议继续执行 `outputs/给拯救者Pi-Agent的长视频分块断点升级提示词.md`。升级后的 8001 会返回 `chunked_analysis: true`，视频默认约 150 秒一块，完成一块立即保存，失败只重试对应分块；8000 暂时不可用时媒体结果也不会丢失。

## 数据说明

- 原始素材保存在当前浏览器，不会自动上传到项目服务器。
- 连接 WeMM 后，建立索引时会向你填写的服务发送缩略图或视频文件。视频由模型服务临时切段，完成后会删除临时文件。
- 清理浏览器站点数据会删除本地素材库。正式团队版应增加服务器对象存储和登录权限。
- 当前版本适合作为单人本地 Beta；对公网开放前还需要账号权限、对象存储、任务队列、备份与监控。
- 从旧版本升级后，视频会重新分析一次以生成分路索引；完成后结果卡会显示“画面语义、台词/旁白、画面文字”等真实命中原因。

## 上传、检索与播放规则

- 素材入库属于后台任务，文字、图片与视频搜索属于交互任务。启用 `cloud/wemm_api.py` 0.4.0 后，后台视频会在每个片段处理完成后主动让出模型，优先响应新搜索，不需要等整条视频分析结束。
- GPU 推理仍然保持单任务执行，避免 8GB 显存同时运行多个模型请求而溢出。搜索最迟需要等待当前正在计算的一个小批次或一个视频片段，不会等待整个素材库入库。
- 图片与文字的后台向量写入按小批次提交；前台搜索结束后会自动继续入库。
- 同一网页以及同一浏览器的其他素材雷达标签页实行单视频播放：新视频开始播放时，其他正在播放的视频会自动暂停，避免两个声音重叠。
- 拯救者升级提示词见 `outputs/给拯救者Pi-Agent的搜索优先队列升级提示词.md`。升级后访问 `/health` 应看到 `priorityScheduling: true`。

## 图片精细检索

- 每张独立图片建立 1 个整图语义向量和 5 个重叠局部区域向量，兼顾整体构图与角落小物体。
- 搜索先用整图向量召回，再对靠前的 40 张候选图融合局部区域、图片文字与元数据重新排序；结果会显示“局部细节”或“图片文字”等命中原因。
- 参考图片也会建立局部向量，因此可以用一张局部构图或小物体相近的图片反查素材。
- 8001 支持独立图片 OCR 后，海报标题、价格、品牌名和包装文字会生成独立文字向量。拯救者升级提示词见 `outputs/给拯救者Pi-Agent的独立图片OCR升级提示词.md`。
- 旧图片无需重新上传；新版网页会在后台补建图片索引。整图与局部索引立即可用，OCR 在 8001 健康接口返回 `image_ocr: true` 后自动启用。

## 模型接口

云端服务提供：

- `GET /health`
- `POST /embed`
- `POST /index-video`，接收原始视频流并返回带起止时间码的片段向量

请求示例：

```json
{
  "dimension": 256,
  "inputs": [
    { "kind": "text", "text": "暖色人物特写" }
  ]
}
```
