# 给拯救者 Pi Agent 的独立图片 OCR 升级提示词

请直接在这台联想拯救者的 WSL2 Ubuntu 中升级现有素材雷达 8001 媒体分析服务。不要只给教程：先检查和备份，再修改、启动并用真实图片验收。不得破坏 8000 WeMM，不得打印、复制或提交完整 API 密钥。

## 目标

现有 8001 的 PaddleOCR 主要用于视频画面。请新增独立图片 OCR，使 Mac 素材雷达能搜索海报标题、品牌名、价格、包装文字和图片中的小字。

## 必须实现

1. 在现有 FastAPI 服务新增 `POST /analyze-image`，复用 `/analyze-video` 相同的 Bearer 鉴权。
2. 接收 multipart 字段 `file`，支持 JPEG、PNG、WebP、BMP、TIFF，单图上限 80MB；校验真实图片内容，不只相信扩展名。
3. 使用已经安装的 PaddleOCR 与 PP-OCRv5 Mobile 模型，不重复下载第二套模型，不占用 WeMM 的 GPU。
4. 大图按比例缩放并保留清晰文字；超长图或海报允许重叠分块 OCR，最后按文本与坐标去重。
5. 返回每条文字的 `text`、`confidence`、`box`，以及真实执行耗时和引擎信息。没有文字应返回空数组，不算失败。
6. 临时文件必须在成功、异常和客户端中断后清理，不保存用户图片。

响应格式：

```json
{
  "width": 1920,
  "height": 1080,
  "ocr": [
    {"text": "限时优惠", "confidence": 0.98, "box": [[10, 20], [200, 20], [200, 70], [10, 70]]}
  ],
  "analysis_receipt": {
    "component": "image_ocr",
    "status": "ready",
    "engine": "PaddleOCR PP-OCRv5 Mobile",
    "elapsed_ms": 320
  },
  "warnings": []
}
```

## 健康接口

在现有 `/health` 响应中增加，不得删除原字段：

```json
{
  "image_ocr": true,
  "capabilities": {
    "image_ocr": true
  }
}
```

网页会用这个能力标记决定是否自动给旧图片补 OCR；因此必须真实可用后才返回 `true`。

## 性能与并发

- 图片 OCR 与视频分析共用受控 CPU 资源，但图片请求不要被一个长视频永久锁死。把图片 OCR 放入短任务优先队列，或允许一个轻量图片 OCR 槽位；总线程数要受限，避免 Windows 卡死。
- 单张普通 1080p 图片目标 1 至 5 秒完成。超长海报可以更慢，但必须有 5 分钟内的服务端超时和清楚错误。
- 某张图片失败不能使 8001 进程退出，也不能留下永远显示 running 的任务锁。

## 验收

至少用三张真实图片测试：普通照片、含中文价格和品牌名的海报、长截图。验证：

1. `/health` 返回 `image_ocr: true`。
2. 三张图都返回 HTTP 200；普通照片无文字时返回 `ocr: []`。
3. 海报能识别标题、价格和品牌名，并有置信度与坐标。
4. 连续请求 10 张图片后没有临时文件堆积、内存持续增长或任务锁死。
5. 同时确认 8000 `/health` 和 8001 原 `/analyze-video` 仍可用。

完成后只汇报：备份路径、修改文件、启动命令、健康响应中新增能力、三张测试图的耗时与 OCR 条数、仍存在的限制。现在开始执行。
